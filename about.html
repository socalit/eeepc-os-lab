How this EeePC 1016P test site is organized

This page explains what the project is documenting, how the tests were judged, and why app support and CPU limits mattered more than just reaching a desktop.

What this project documents

This site is focused on one laptop: the ASUS EeePC 1016P. The goal is not to list every distro in theory. The goal is to show what actually happened on the hardware, which apps still worked, and where the bottlenecks showed up.

How the results are judged

These are real-world findings, not synthetic benchmarks. Streaming support, browser behavior, app compatibility, keyboard shortcuts, and crash behavior mattered more than whether an installer simply booted.

Methodology

  • Install operating systems that are realistic candidates for Atom-era netbooks.
  • Check whether the system is actually usable after install, not just whether it boots.
  • Record modern app and browser limits, especially streaming and DRM issues.
  • Document which Android builds were too heavy to fully test because of the CPU.
  • Favor practical outcomes: what lets the laptop do useful work today.
Key interpretation rule: when Bliss OS, PrimeOS, and Phoenix OS failed to run well, that was documented as a hardware limitation first. The Atom N455 CPU with 1 core and 2 threads is the main ceiling on this machine.

What counted as success

  • OS installed cleanly
  • UI stayed stable
  • Apps could be launched and used
  • Basic media tasks were possible
  • Keyboard shortcuts and laptop-specific behavior worked where relevant

What counted as failure or limitation

  • Repeated crashes or instability
  • Unsupported apps or broken APIs
  • DRM blocks on 32-bit Linux
  • Browser updates that made the system unusable
  • CPU saturation that prevented normal daily use
